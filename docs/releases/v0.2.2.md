# LocalBridge MCP v0.2.2

Source-only patch release. Package publication remains disabled (`private: true`), and Runtime.app / tunnel deployment requires a separate controlled rollout.

## Improvements

- Backward-compatible terminal result fields `status`, `isComplete`, and `exitCode` distinguish initial wait, prompts, child-process exit, and spawn/process errors. Existing `isBlocked` is a legacy wait hint, not a policy ruling.
- Prompt recognition and process error handling are more reliable; same-PID output follow-up continues to work when initial waiting ends before process completion.
- MCP shell tool descriptions explicitly distinguish terminal waits, LocalBridge policy errors, and independent client/platform tool-safety refusals.
- Release preflight supports explicitly scoped static, offline and network phases, caller-supplied branch/version and isolated scratch directories, with fail-closed source provenance and privacy gates.
- New Git author/committer identities must be GitHub noreply. The proposed Option A offline rewrite sanitizes the sole maintainer's historical identity and concrete local paths, preserving unrelated contributor attribution; the new v0.2.1 baseline SHA is provisionally pinned in the isolated candidate. All reachable history still undergoes content and sensitive-filename scanning. The public history rewrite and revised tag identities are NOT published or approved yet, and the public release remains on HOLD.
- Added regression coverage for terminal result semantics and tool discovery, and made final search test fixtures independent of repository ignore rules.

## Security and compatibility

- All existing LocalBridge `blockedCommands` enforcement, filesystem allowlists, and tool security annotations remain in place.
- Existing bare SSH commands retain the legacy `-t` default, but explicit `-T`, `-tt`, and `RequestTTY=no` options are honored in the locally tested source candidate. SSH command argument logging no longer echoes raw command text. No live SSH/network compatibility or deployment claim is made.
- This source release does not change a ChatGPT platform-level safety policy, tunnel credentials, TCC identity, plugin installation, or user security configuration.
- Actual GitHub CI/CodeQL, release provenance, and rollout readiness must be checked against their real receipts; source content is not their proof.

## Runtime rollout

Keep the existing working v0.2.1 Runtime.app and Tunnel installation until an independently verified backup, bounded health probe, out-of-band recovery/rollback channel, and idle-worker window are available. Upgrade the deployed source from a verified release tag, then validate exact commit/version, health, tunnel connectivity, policy fail-closed and ChatGPT plugin tools. Revert on failed readiness. A source release alone does not authorize live service restart.
