# Daniel Commander v0.1.0-rc.2

Second public-release candidate of Daniel Commander.

This RC supersedes v0.1.0-rc.1 after closing the original P8 lifecycle requirement. It remains a release candidate: original P9 row-by-row qualification is still required before any final `DANIEL_COMMANDER_V0_1_PASS` declaration.

Daniel Commander is a self-hosted MCP computer-control server for filesystem, search, surgical editing, persistent terminal sessions, Git workflows, and SSH.

## Included

- 17 focused MCP tools.
- Portable stdio core qualified on macOS and Linux.
- TCC-aware macOS login runtime with launchd supervision.
- User-owned OpenAI Secure MCP Tunnel deployment path.
- Fail-closed filesystem configuration.
- Clean-room setup and diagnostics.
- Crash recovery for tunnel and Runtime.app failures.
- Active-only macOS sleep prevention while the production tunnel is alive.
- macOS/Linux CI on Node.js 20 and 24.
- SHA-pinned GitHub Actions.
- Security, contribution, portability, and release documentation.

## Changes since v0.1.0-rc.1

- Added a supervised macOS tunnel wrapper that starts `/usr/bin/caffeinate -i -w <tunnel-pid>` only while the production tunnel child is alive.
- Added runtime status reporting for the validated production caffeinate relationship with `CAFFEINATE_COUNT` and `CAFFEINATE_PID`.
- Repaired macOS update lifecycle so the LaunchAgent is reloaded after environment changes instead of relying only on `launchctl kickstart -k`.
- Added original P8 lifecycle regression coverage and qualification documentation.
- Qualified the latest public main commit with CI and CodeQL after the P8 repair.

## Security model

Daniel Commander is intentionally privileged. Filesystem allowlists and command blocklists are guardrails, not an operating-system sandbox. Terminal commands run with the permissions of the account that launches Daniel Commander.

Do not expose an unauthenticated shell-capable MCP endpoint to the public Internet.

## Known boundaries

- Windows is not yet qualified.
- Linux production service management is not yet implemented.
- No hosted relay or shared credentials are provided.
- npm publication is disabled.
- The macOS Runtime.app is created locally and is not distributed as a notarized binary.
- Active-only macOS no-sleep behavior is qualified for the local production tunnel lifecycle, not for display wake, lid-close override, or non-macOS service management.
- Original P9 full-matrix qualification remains open.
